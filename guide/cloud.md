# IPARK 클라우드 2.0 사용 안내

## 등록

단지, 동·호, 10자 이내 기기 이름(예: `HA`)을 입력합니다. 월패드에서 **설정 → 모바일 기기 등록 → 등록** 화면을 연 뒤 HA 양식을 제출하세요. 제출하면 인증번호를 요청합니다. 월패드의 6자리 번호를 HA에 입력하면 검증과 로그인이 이어집니다.

응답을 확인하지 못했을 때에는 등록이 이미 처리됐을 수 있으니 월패드 상태를 확인하세요. 인증번호가 만료되면 **새 번호 요청**을 선택합니다. 등록 화면으로 돌아간 뒤 다시 제출해야 새 요청이 전송됩니다. 같은 설정 흐름에서는 UUID가 유지됩니다. 인증이 성공하고 로그인만 실패하면 로그인만 다시 시도하는 화면이 표시됩니다.

기존 UUID가 있으면 **기존 UUID로 연결**을 선택합니다. IP 주소와 엘리베이터 수는 기존 관리자 API의 층수·방향 센서가 필요한 경우에만 지정하세요. 새 호출 버튼에는 필요 없습니다.

## 기존 설치 교체

이 포크도 `custom_components/bestin`과 `bestin` 도메인을 사용합니다. 먼저 HA 백업을 만드세요. 기존 BESTIN 통합 설정 항목을 삭제하지 말고, HACS 저장소를 교체한 뒤 다운로드·재시작합니다. 두 저장소를 동시에 설치하지 마세요. 수동 설치 시에는 이 저장소의 `custom_components/bestin` 전체 폴더로 기존 폴더를 교체합니다.

기존 UUID 및 장치 ID를 변경하는 마이그레이션은 하지 않습니다. 새 일반 호출 버튼만 추가됩니다. 기존 위치 센서와 스위치는 월패드 IP가 설정된 항목에서 유지됩니다.

## 엘리베이터

허브 기기에 **엘리베이터 상향 호출 / 하향 호출** 버튼이 생성됩니다. HA 대시보드에서 누르거나 자동화의 `button.press`로 실행하세요. 엔티티 ID는 통합의 기기 화면에서 확인합니다.

```yaml
action: button.press
target:
  entity_id: button.your_actual_elevator_down_entity
```

위 ID는 예시이므로 실제 엔티티로 바꾸세요.

- 단지 정보에 지원이 명시되면 활성화됩니다.
- 단지 정보가 없거나 조회에 실패하면 기본 비활성화됩니다. 공식 앱에서 호출 가능한 것을 확인한 뒤 설정 → 기기 및 서비스 → 엔티티에서 비활성 엔티티를 찾아 직접 활성화할 수 있습니다.
- 단지 정보가 명시적으로 미지원이면 버튼을 생성하지 않습니다.
- 성공은 호출 요청 성공이며 **도착 확인이 아닙니다**. 층수·방향 센서는 기존 IP 기반 관리자 SSE 방식입니다.
- 타임아웃 때 중복 호출을 피하려고 자동 재시도하지 않습니다. 실제 엘리베이터를 확인한 뒤 다시 누르세요.
- 인증 오류가 계속되면 통합을 다시 불러오세요. UUID 인증이 만료되면 HA의 재인증 흐름에서 같은 UUID로 월패드 등록을 다시 진행합니다.

## 공동현관

클라우드 2.0으로 연결하면 출입 가능한 문 목록을 조회해 허브 기기에
**공동현관 열기 · 로비폰 이름** 버튼을 생성합니다. 공식 앱에서 onepass를
지원하는 단지에 한하며, 월패드 IP는 필요하지 않습니다.

설정 → 기기 및 서비스 → BESTIN → 기기에서 문 이름을 확인하고 버튼을 누르세요.
대시보드나 자동화에서도 실제 엔티티 ID를 지정해 `button.press`로 실행할 수 있습니다.
버튼은 실제 출입문 개방을 요청합니다. 잠김·열림 상태를 나타내는 센서는 아닙니다.
요청 성공도 실제 문 열림을 확인한 것은 아닙니다.

- 목록이 없거나 단지가 명시적으로 미지원이면 버튼을 만들지 않습니다.
- 목록 조회 실패는 다른 장치의 사용을 막지 않습니다. 공식 앱의 출입문 목록을 확인한 뒤 통합을 다시 불러오세요.
- 문 추가·이름 변경도 통합을 다시 불러오면 반영됩니다. 목록을 주기적으로 조회하지 않습니다.
- 개방 요청은 공식 앱의 앱 이름과 로그인 세션의 기기 별칭을 전송합니다. 별칭이 없으면 요청하지 않습니다. 통합을 다시 불러오고 기기 등록을 확인하세요.
- 실패·타임아웃은 HA 오류로 표시하며 자동 재시도하지 않습니다. 실제 문 상태를 확인한 뒤 다시 누르세요.
- 실제 단지의 목록 응답과 문 열기는 아직 검증하지 않았습니다.

## Google Home와 SmartThings

조명·난방은 별도 [Google Assistant 통합](https://www.home-assistant.io/integrations/google_assistant/)을 통해 노출할 수 있습니다. 엘리베이터는 HA 스크립트에서 버튼을 실행한 뒤 스크립트를 Google에 노출하는 방식입니다. 외부 연결 설정은 이 통합에 포함되지 않습니다.

기본 [SmartThings 통합](https://www.home-assistant.io/integrations/smartthings/)은 SmartThings 기기를 HA로 가져오는 방향입니다. 이 컴포넌트가 월패드 기기를 SmartThings로 자동 내보내지는 않습니다.

## 인증과 검증 범위

인증번호와 transaction은 설정 흐름 안에서만 사용하고 HA 설정 항목에 저장하지 않습니다. UUID와 로그인 세션은 HA 설정 저장소에 보관되므로 HA 백업도 보호하세요. 사이트가 HTTP 주소를 제공하면 그 단지 API 통신은 HTTP로 이루어집니다.

앱 1.5.4의 API 구조를 분석했고, 공식 단지 목록만 읽기 전용으로 조회했습니다. 실제 기기 등록·세대 제어·엘리베이터 호출과 단지별 응답은 아직 검증하지 않았습니다. 원본 전체 기능이나 모든 단지 지원을 보장하지 않습니다.
